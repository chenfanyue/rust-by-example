### Unsafe Rust
#### 原始指针与手动内存管理

1. **原始指针简介**
   - 在 Rust 中，默认情况下使用的是安全指针（如引用 `&` 和可变引用 `&mut`），它们在编译时被 Rust 编译器严格检查，以确保内存安全。
   - 原始指针（Raw Pointers）是一种不受 Rust 编译器内存安全检查约束的指针类型，主要包括：
     - `*const T`：不可变的原始指针，指向类型 `T`。
     - `*mut T`：可变的原始指针，指向类型 `T`。
   - 原始指针允许进行更多底层操作，如跨越借用检查、手动内存管理和与外部 C 代码的交互，但由于它们不受所有权和借用规则的保护，因此存在潜在的内存安全风险。

2. **创建原始指针**
   - 原始指针可以通过引用（`&T` 或 `&mut T`）转换获得，使用 `as` 关键字进行转换：
     ```rust
     let x: i32 = 42;
     let raw_ptr: *const i32 = &x as *const i32;
     let raw_mut_ptr: *mut i32 = &x as *mut i32;
     ```
   - 需要注意的是，从引用转换为原始指针的过程是安全的，但解引用原始指针是**不安全的**，必须在 `unsafe` 块中完成。

3. **原始指针的解引用**
   - 解引用原始指针是指通过访问指针指向的内存地址来读取或写入值。由于编译器无法保证这些内存地址的有效性，因此解引用必须放在 `unsafe` 块中进行：
     ```rust
     unsafe {
         println!("Value at raw_ptr: {}", *raw_ptr);
     }
     ```
   - 错误地解引用无效指针可能导致**未定义行为**，包括程序崩溃或数据损坏。

4. **手动内存管理**
   - Rust 默认使用所有权和借用系统来自动管理内存，但在 `unsafe` 块中，程序员可以手动分配和释放内存，从而绕过 Rust 的所有权系统。
   - 手动内存管理通常通过 `std::alloc` 模块来实现，提供了底层的内存分配和释放操作：
     ```rust
    use std::alloc::{alloc, dealloc, Layout};

    fn main() {
        let layout = Layout::new::<i32>();
        unsafe {
            // 手动分配内存
            let ptr = alloc(layout) as *mut i32;
            if !ptr.is_null() {
                *ptr = 1001;
            }
            // 使用完毕后释放内存
            dealloc(ptr as *mut u8, layout);
        }
    }
     ```
   - 这里的 `alloc` 函数用于分配指定布局大小的内存，而 `dealloc` 用于释放内存。在这种场景下，程序员必须确保手动释放所有分配的内存，否则会造成内存泄漏。

5. **与外部代码的交互（FFI）**
   - 原始指针在与 C 语言等其他编程语言进行外部函数接口（FFI）交互时尤为重要。由于其他语言的内存模型不同，Rust 的引用可能无法直接传递给 C 函数，因此必须使用原始指针：
     ```rust
     extern "C" {
         fn some_c_function(ptr: *const i32);
     }

     let x: i32 = 42;
     unsafe {
         some_c_function(&x as *const i32);
     }
     ```

6. **原始指针的风险**
   - 使用原始指针需要特别小心，因为它可能引入以下风险：
     - **空指针解引用**：访问空指针或无效地址可能导致崩溃。
     - **悬空指针**：指针指向已释放的内存区域，解引用悬空指针可能导致未定义行为。
     - **数据竞争**：多个可变指针同时访问相同内存可能导致数据不一致。
   - 为了避免这些问题，建议仅在绝对必要时使用原始指针，并尽量通过封装和测试来确保内存安全。
