### 测试与调试

#### 单元测试与集成测试

##### 1. 单元测试 (Unit Testing)

- **概述**
  - 单元测试是一种对代码中的最小可测试部分进行验证的方式，通常用于测试函数、方法或模块的正确性。
  - Rust 提供了内置的测试框架，通过使用 `#[test]` 标注测试函数来实现单元测试。

- **基本语法**
  - 在 Rust 中，测试函数与普通函数类似，但使用 `#[test]` 属性标注。
  - 测试函数无需显式返回值，通常通过 `assert!`、`assert_eq!` 和 `assert_ne!` 宏来进行断言。

  ```rust
  #[cfg(test)]
  mod tests {
      #[test]
      fn it_works() {
          assert_eq!(2 + 2, 4);
      }

      #[test]
      fn test_fails() {
          assert!(1 == 2); // 此测试将失败
      }
  }
  ```

- **断言宏**
  - `assert!`: 断言表达式为真。
  - `assert_eq!`: 断言两个表达式相等。
  - `assert_ne!`: 断言两个表达式不相等。
  
- **测试模块**
  - 使用 `#[cfg(test)]` 来标记包含测试代码的模块，该模块仅在运行测试时编译，不会包含在常规构建中。

- **常见实践**
  - **命名规范**: 测试函数应具有描述性名称，能清晰反映测试的目标。
  - **边界条件测试**: 编写测试来涵盖所有可能的边界条件，如极大或极小输入值。
  - **错误处理测试**: 测试函数如何应对错误条件或无效输入。

##### 2. 集成测试 (Integration Testing)

- **概述**
  - 集成测试用于测试多个模块之间的交互，通常测试应用程序的公共接口，而不是具体的内部实现细节。
  - 集成测试通常位于 `tests` 目录中，并被视为独立的二进制项目。

- **基本语法**
  - 集成测试不需要 `#[cfg(test)]`，因为它们默认是在 `tests` 目录中的单独文件中定义的。
  - 每个文件中的测试都可以看作一个独立的 crate，因此需要导入被测模块。

  ```rust
  // 在 tests/integration_test.rs 中
  use my_crate::some_function;

  #[test]
  fn integration_test() {
      assert_eq!(some_function(2), 4);
  }
  ```

- **目录结构**
  - 集成测试文件应放置在 `tests/` 目录中，每个文件会被视为一个单独的 crate：
  
  ```
  my_project/
  ├── src/
  │   ├── lib.rs
  ├── tests/
  │   ├── integration_test.rs
  ```

- **多个测试文件**
  - Rust 的集成测试支持多个文件，每个文件中的测试都可以独立运行，通常用于测试项目的不同方面。

##### 3. `cargo test` 命令

- **运行测试**
  - 使用 `cargo test` 可以运行所有单元测试和集成测试。该命令会自动查找带有 `#[test]` 标记的函数，并执行它们。

- **过滤测试**
  - 可以通过指定测试名称来运行特定的测试。例子：`cargo test test_name`。
  
- **显示测试输出**
  - 默认情况下，测试代码中的输出会被隐藏。要查看输出，可以使用 `cargo test -- --nocapture`。

- **并行执行**
  - Rust 的测试框架默认并行执行测试，使用 `--test-threads` 参数可以指定测试线程数：`cargo test -- --test-threads=1`。

##### 4. 测试代码的调试

- **调试测试**
  - 可以使用调试器（如 `gdb` 或 `lldb`）来调试测试函数。例如：
  
  ```bash
  cargo test -- --nocapture --test-threads=1
  ```

- **断言失败时打印输出**
  - 测试断言失败时，可以查看详细的错误信息以定位问题。通过 `println!` 宏，可以打印调试信息来帮助跟踪问题。

##### 5. 测试覆盖率 (Code Coverage)

- **工具支持**
  - 可以使用 `tarpaulin` 工具来生成测试覆盖率报告：
  
  ```bash
  cargo install cargo-tarpaulin
  cargo tarpaulin
  ```

- **分析覆盖率**
  - 通过分析覆盖率报告，可以发现未被测试的代码路径，并编写额外的测试来提高覆盖率。
