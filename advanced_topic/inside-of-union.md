在 Rust 中，`union`（联合体）与 C 语言中的联合体相似，允许多个字段共享相同的内存空间。虽然你可以定义多个字段，但这些字段确实是互斥地共享内存空间的。也就是说，在任何给定的时间，联合体的所有字段都指向同一个存储位置，而实际上只有一个字段会被初始化和使用。其他字段的值是不确定的，因此读取它们可能会得到未定义行为或垃圾值。

### 为什么 `f1` 和 `f2` 都能输出值？

在这段代码中：

```rust
union MyUnion {
    f1: u32,
    f2: f32,
}

fn main() {
    let u = MyUnion { f1: 1 }; // 初始化 f1 字段

    unsafe {
        println!("{}", u.f1); // 读取 f1
        println!("{}", u.f2); // 读取 f2
    }
}
```

你在初始化联合体 `u` 时，只给 `f1` 赋值，但在之后却读取了 `f2`。由于 `f1` 和 `f2` 共享相同的内存地址，`f2` 的值其实是解释 `f1` 的二进制位模式为一个 `f32` 类型浮点数。这导致输出的 `f2` 是一个无意义的浮点值，因为 `1`（`f1` 的值）以浮点格式解析出来是一个非常小的浮点数值。

这种情况正是联合体的本质：内存是共享的，但是类型信息是分开的。每个字段在物理上是相同的一块内存，但逻辑上解释方式不同。实际上，在你的代码中，Rust 并没有“初始化” `f2`，你只是用 `f32` 的视角去查看它。

### 联合体如何共享内存空间？

联合体中的所有字段会占用相同的内存空间。联合体的大小等于其最大的字段所需的内存空间。例如：

- `f1: u32` 占用 4 个字节（32 位）。
- `f2: f32` 也占用 4 个字节。

由于 `f1` 和 `f2` 都是 4 字节长的类型，联合体 `MyUnion` 也会占用 4 个字节的内存。Rust 将这些字段存储在同一块内存地址上，但只允许你通过 `unsafe` 代码块访问它们，因为 Rust 无法保证你访问的是正确的字段。

### 互斥地共享内存空间

理论上，联合体的字段确实是互斥共享内存的。在任何时间点，只应初始化和使用一个字段。换句话说，虽然联合体的多个字段共用一块内存，但你在正确的上下文中只能安全地访问那个你已经初始化的字段。

如果你尝试读取未初始化的字段（在你的例子中，`f2`），Rust 无法保证这个字段能返回有意义的值，这就是为什么你在输出 `f2` 时看到一个奇怪的浮点数。

**重要提醒：**
你在这种情况下访问未初始化字段是潜在不安全的行为，可能会导致未定义行为（UB）。Rust 通过 `unsafe` 明确表明这些操作需要开发者自行确保安全性。

### 小结

```rust
union MyUnion {
    f1: u32,
    f2: f32,
}

fn main() {
    let mut u = MyUnion { f1: 1 };
    unsafe {
        println!("{}", u.f1);
        println!("{}", u.f2); // 未定义行为
    }

    u = MyUnion { f2: 1.0 };
    unsafe {
        println!("{}", u.f1); // 未定义行为
        println!("{}", u.f2);
    }
}
```

- 联合体中的所有字段共享同一块内存空间。
- 你只能在 `unsafe` 代码块中访问联合体的字段，因为 Rust 无法确保你访问的字段是正确的。
- 如果读取未初始化的字段，会得到未定义行为（UB），因为其底层数据可能不是这个字段对应的类型。
- 联合体字段共享内存空间的行为是互斥的，虽然在内存层面它们共用空间，但逻辑上一次只能使用一个字段。
